SYSTEM DESCRIPTION:
This is a Library Management System that manages books, members, and borrowing operations.

EXISTING SYSTEM COMPONENTS:
1. Books: Each book has a unique ID, title, author, and ISBN
2. Members: Each member has a unique ID, name, and membership status
3. Current system tracks which books are available and which are checked out

REQUIREMENTS FOR NEW MODULE: Enhanced Borrowing System

FUNCTIONAL REQUIREMENTS:

FR1: Book Borrowing
- Members can borrow books if they are available
- A member can borrow at most 3 books at a time
- A book can only be borrowed by one member at a time

FR2: Book Returning
- Members can return books they have borrowed
- Upon return, the book becomes available again

FR3: Reservations
- Members can reserve books that are currently borrowed
- When a reserved book is returned, it should be held for the member who reserved it
- A book can have multiple reservations, handled in FIFO order
- A member can have at most 2 active reservations

FR4: Overdue Management
- Books can be borrowed for a maximum period (e.g., 14 days)
- If a book is overdue, the member cannot borrow more books until it is returned
- Members with overdue books cannot make new reservations

CONSTRAINTS:
- The system must maintain data consistency
- No book should be in an invalid state (e.g., both available and borrowed)
- Members must exist in the system before they can borrow or reserve books

QUESTIONS TO CLARIFY:
- What happens if a member tries to reserve a book they already have borrowed?
- Can a member reserve a book that is currently available?
- What happens to reservations when a member's membership expires?
- Should there be a time limit for picking up reserved books?
