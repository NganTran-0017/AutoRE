# Alloy Analyzer Filename Parsing Fix

## Issue

When Alloy Analyzer 6 executes a model with run and check commands, it generates JSON output files with filenames in the format:
```
<command_name>-solution-<N>.json
```

For example:
- `All_Requirements-solution-0.json`
- `assertR1-solution-0.json`
- `R1-solution-0.json`

However, the analyzer result parsing code was extracting the command name directly from `file_path.stem`, which would give:
- `All_Requirements-solution-0` (incorrect)
- `assertR1-solution-0` (incorrect)
- `R1-solution-0` (incorrect)

When the code tried to look up these names in the `command_map` (which contained keys like `All_Requirements`, `assertR1`, `R1`), it couldn't find matches, causing all results to be categorized as "unknown" and not properly counted.

## Symptoms

The bug manifested as:
- Analyzer results showing "COUNTEREXAMPLES: None" when counterexamples actually existed
- Analyzer results showing "SATISFYING INSTANCES: None found" when instances actually existed
- Evaluator receiving incorrect information about verification results

## Root Cause

In `src/utils/alloy_executor.py`, method `_analyze_results()` at line ~420:

```python
# OLD CODE (INCORRECT)
cmd_name = file_path.stem  # Gets filename without extension
```

For a file like `All_Requirements-solution-0.json`:
- `file_path.stem` returns `All_Requirements-solution-0`
- Lookup in `command_map` for key `All_Requirements-solution-0` fails
- File is not properly categorized

## Fix

Updated the code to strip the `-solution-N` suffix:

```python
# NEW CODE (CORRECT)
# Extract command name from filename
# Handle formats like "All_Requirements-solution-0.json" -> "All_Requirements"
# or "ChainedEmergencyScenario.json" -> "ChainedEmergencyScenario"
filename_stem = file_path.stem  # Gets filename without extension

# Strip "-solution-N" suffix if present
if '-solution-' in filename_stem:
    cmd_name = filename_stem.rsplit('-solution-', 1)[0]
else:
    cmd_name = filename_stem
```

This extracts the correct command name:
- `All_Requirements-solution-0.json` → `All_Requirements` ✓
- `assertR1-solution-0.json` → `assertR1` ✓
- `R1-solution-0.json` → `R1` ✓

## Impact

This fix ensures that:
1. All SAT results from run commands are correctly identified as satisfying instances
2. All SAT results from check commands are correctly identified as counterexamples
3. All UNSAT results are correctly tracked
4. The Evaluator receives accurate information about verification results
5. Users see correct feedback about model verification status

## Related Issues

This bug was preventing the Evaluator from properly analyzing verification results, leading to:
- Incorrect feedback generation
- Missed issues in the model
- Incorrect convergence decisions

The fix resolves these downstream issues by ensuring accurate result parsing.
